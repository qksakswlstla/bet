# 다섯 대회 분석·시뮬레이션 실험실

대상은 **KBL, KOVO(남자부/여자부), NBA, J리그컵, AFC 챔피언스리그 엘리트**입니다. 다른 대회는 입력 검수에서 제외합니다. API 키 없이 예시로 실행됩니다. 실제 경기 자료·시즌 규정·베트맨 상품은 자동 연결하지 않았습니다. 실제 학습과 과거 성능 검증은 미완료이며 추천은 항상 보류합니다.

## Windows 설치·업데이트

1. [GitHub](https://github.com/qksakswlstla/bet)의 **Code → Download ZIP**으로 최신 코드를 받습니다.
2. 기존 앱 명령 창에서 Ctrl+C로 종료합니다. 기존 폴더의 `data`를 백업합니다. 새 ZIP은 새 폴더에 풉니다.
3. Python 3.12 64비트 설치 후 새 폴더의 `install_windows.bat`을 실행합니다.
4. `start_windows.bat`을 실행합니다. 처음 Email 질문이 나오면 빈 상태로 Enter를 누릅니다.
5. 브라우저가 자동으로 열리지 않으면 실행 창에 표시된 로컬 주소를 주소창에 입력합니다.

PowerShell 명령을 사용하려면 `app.py`가 있는 폴더에서:

```powershell
cd "C:\Users\사용자이름\Downloads\bet-main"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

Linux/Codex에서는 `/workspace/bet`에서 `.venv/bin/python`을 사용합니다. 테스트 명령은 `python -m pytest -q`입니다. Windows 직접 실행 테스트는 아직 하지 않았습니다.

## 처음 사용할 순서

1. 왼쪽에서 대회와 KOVO 부문을 선택합니다. **예시 데이터**의 여섯 화면부터 확인합니다.
2. 경기 상세에서 승패·상품 확률, 배당 기준과의 차이, 점수차·총득점 분포를 확인합니다.
3. 시나리오에서 조건 이름과 수치를 바꿉니다. 사건 이름만 선택하면 계수가 자동 추정되는 것은 아닙니다. 근거를 기록하세요.
4. 조합 화면에서는 다른 대회를 섞어 선택할 수 있습니다. 같은 경기의 두 상품은 같은 조합에서 제외합니다.
5. 실제 자료는 **실제/예시 자료 입력**에서 직접 입력하거나 앱에서 받은 CSV 양식으로 입력합니다. 입력 목록은 CSV로 내려받아 보관하세요. 브라우저 세션 입력과 고정 예측 기록은 다릅니다.
6. 경기 전에 예측을 고정 저장하고 공식 종료 뒤 성능 기록에 결과를 입력합니다.

## 자료 형식과 경계

새 양식은 `examples/matches_template.csv`, 예시는 `examples/example_matches.csv`입니다. UTF-8 CSV, 최대 2MB/100행입니다. v1 축구 전용 CSV는 새 필드가 없으므로 그대로 가져올 수 없습니다. 스크린샷 자동 인식은 지원하지 않습니다.

- `competition`: 위 다섯 이름 중 하나. `division`: KOVO는 남자부/여자부, 나머지는 `해당 없음`.
- `season`, `stage`: 공식 출처로 확인한 시즌·단계를 직접 기입합니다. 앱이 현재 시즌을 추정하지 않습니다.
- `match_id`, `home_id`, `away_id`: 대회·시즌·부문 내 고정 ID. 공급원별 팀 표시 이름은 달라도 같은 팀이면 같은 ID를 지정합니다. `provider`에 공급원 이름을 적습니다. 자동 팀 매칭은 없습니다. CSV와 예측 기록에 매핑이 보존됩니다.
- `kickoff`, `deadline`, `as_of`, `collected_at`: 시작·마감·정보 기준·수집 시각. 예: `2026-11-01T19:00:00+09:00`. 화면의 주요 시각은 KST이며 내보내기는 시간대 포함 ISO 형식입니다.
- `kind`: `real` 또는 `example`. `source`: 출처. 행의 모든 값에 공통 출처·시각을 적용합니다. 개별 근거는 `evidence`에 추가합니다.
- `market`, `line`: 상품 범위와 기준점. 승패는 기준점 빈칸. 홈 핸디캡은 부호를 포함합니다. 실제 베트맨 제공 여부는 직접 확인해야 합니다.
- `odds`: 선택지별 배당 JSON. 승패는 `{"home":1.9,"away":1.9}`, 축구 3-way는 `draw` 추가, 총득점은 `over`/`under`. 서로 다른 시점·상품 배당 혼합 금지.
- `rules_version`, `rules_source`: 해당 시즌·단계의 공식 경기 방식과 상품 정산 범위를 구분할 근거를 기록합니다.
- `rules_verified`, `model_inputs_supported`: 실제 자료의 규칙/입력 근거를 사용자가 확인했을 때만 `true`. 앱이 공식 검증을 대신했다는 뜻이 아닙니다. 미확인이면 확률 보류.
- `combination_verified`, `odds_available_verified`: 실제 조합 가능 여부·당시 구매 가능 배당 확인. 미확인이면 실제 조합 비교에서 제외합니다.
- `source_conflict`: 출처 충돌 시 `true`로 표시하면 분석 보류.
- `basis`: 표본 수, 기대값 산출 근거, 누락·미확정 항목을 서술합니다.
- `evidence`: `[{"type":"official","source":"자료명/URL","as_of":"시각","collected_at":"시각","note":"내용"}]`. `type`은 공식 발표 `official`, 보도 `report`, 분석자 가정 `assumption`. 선수·라인업·날씨·동기·로테이션을 확정 사실로 승격시키지 않습니다. 미확보면 `[]`.
- `params`: 아래 종목별 수치 JSON. 직접 입력 화면에서는 한국어 숫자 칸으로 입력합니다. 빠진 값은 임의로 대체하지 않고 계산을 보류합니다.

CSV의 JSON은 큰따옴표 이스케이프가 필요하므로 앱의 예시 CSV를 내려받아 구조를 참고하세요. 예시 수치를 실제 경기 값으로 복사하지 마세요. API 키는 필요 없으며 향후 연결 시 환경변수로만 관리합니다.

## 모형과 계산 가정

**모든 모형은 사용자 수치로 조건부 결과를 계산하는 초기 구현입니다. 대회별 학습 계수나 경기 예측 성능이 확보된 상태가 아닙니다.** 같은 종목의 실행 코드는 공유하지만 실제 수치·학습 데이터·평가는 대회별로 구분합니다. 예시 수치는 가상 가정입니다.

### KBL·NBA

입력: `pace`(팀당 공격 횟수), `pace_sd`(공통 속도 표준편차), `home_eff`/`away_eff`(공격당 기대득점), `residual_sd`(팀 득점 잔차 표준편차), `close_pace`/`blowout_pace`(후반 속도 배수), `overtime_fraction`(연장 1회 공격 횟수/정규경기 공격 횟수).

두 팀에 공통 속도를 추출한 뒤 전반 득점을 생성합니다. 전반 차이 5점 이하는 접전, 15점 이상은 큰 차이로 가정해 후반 속도를 변경합니다. 이 경계와 모형 구조도 검증된 전술 효과가 아닙니다. 동점이면 입력한 연장 비율로 추가 득점을 생성해 승패를 결정합니다. 출력은 연장 포함 승패·반점 점수 핸디캡·반점 총득점입니다. 실제 시즌 규칙을 공식 확인하기 전에는 예시 계산입니다.

선수 결장·시간 제한·파울·리바운드·턴오버·자유투·슛·일정은 확보된 근거를 기록하고 효율/속도/변동 가정으로 직접 반영합니다. 자동 선수 기여도나 상대 보정 학습은 아직 없습니다. KBL 실제 계수를 NBA에 자동 복사하지 않습니다. 농구 경기 중 분석은 미지원입니다.

### KOVO 남자부·여자부

입력: `rally_home`(홈 랠리 승률), `fatigue_per_set`(세트마다 확률 변화), `substitution_delta`(교체 후 확률 변화), `substitution_after_point`(세트 내 합계 득점이 이 값 이상일 때 교체 효과 적용).

매 랠리를 생성해 1~4세트 25점, 5세트 15점, 2점차, 3세트 선승이라는 **가정 규칙**으로 종료합니다. 선수 교체와 체력 변화는 사용자 가정이며 확률을 0.01~0.99로 제한합니다. 서브권·로테이션·선수별 공격/리시브/블로킹/범실을 학습하지 않은 단순 모형입니다. 세트 점수에서 경기 승패·세트 핸디캡·경기 총득점을 일관되게 계산합니다. 듀스 수렴에 실패하면 결과를 버리고 오류를 표시합니다. 남녀 데이터를 합치지 않습니다. 실제 규정의 시즌별 확인은 미완료입니다.

### J리그컵·AFC 챔피언스리그 엘리트

입력: `home_xg`, `away_xg`, `minute`, `home_score`, `away_score`. 사전 기록은 경과 시간·현재 점수 모두 0. 득점 독립 포아송으로 90분 승무패·정수 홈 3-way 핸디캡·반골 총득점을 계산합니다. 연장·승부차기·진출 결과는 포함하지 않습니다. 진출 모형은 미구현입니다.

수동 상황 계산은 남은 시간에 기대득점을 비례 조정해 현재 점수를 더합니다. 퇴장·로테이션·진출 조건별 경기 운영은 근거 있는 기대득점 변경 가정으로만 비교합니다. 실제 경기 중 피드는 없습니다. 상대 보정·선수 영향·저득점 상관·2차전 전략 모형은 아직 없습니다.

### 공통

시나리오 발생 확률은 미확보입니다. 겹치는 시나리오를 합산하지 않습니다. 1천/5천/2만 회와 시드·입력·모형 버전·자료·계산 시각을 JSON으로 내보냅니다. 실행 횟수가 정확도 증거는 아닙니다. 표시 분위·분포는 모형 가정하의 변동이며 모형 정확도의 신뢰구간이 아닙니다.

조합은 기본 2~3경기, 최대 10개 선택에서 비교합니다. 경기 간 독립 확률곱과 배당곱을 가정합니다. 같은 경기의 다른 상품은 독립 사건으로 취급하지 않습니다. 경기 간 상관·공통 모형 오류·추정 오차의 크기는 미확보이며 추천 보류입니다. 기대순손익은 고정 예산×(확률×배당−1). 실제 상품의 조합 제한·취소·연기·세금·상한은 자동 연결하지 않습니다. 자동 구매·손실 만회 증액 기능은 없습니다.

## 예측 기록·성능

`data/multi_history.sqlite3`에 첫 사전 예측을 고정 저장합니다. v1 `data/history.sqlite3`은 보존하며 대회 정보가 없는 기록을 추측해서 합치지 않습니다. `BET_DATA_DIR` 환경변수로 저장 폴더를 바꿀 수 있습니다. 앱 종료 후 DB를 복사해 백업하세요.

공식 결과 입력은 축구 `{"regulation":[1,1]}`, 농구 `{"including_overtime":[90,88]}`, 배구 `{"sets":[[25,20],[25,21],[25,22]]}`입니다. 공식 결과 원문과 **선택한 상품의 정산 결과**를 별도로 저장합니다. 축구 정규시간 무승부와 연장 승리를 혼동하지 않습니다. 취소·연기·몰수 등 특수 정산은 이 버전에서 입력하지 마세요.

대회·시즌·부문·상품·기준점·규칙·모형 버전·실제/예시별로 표본/기간, Brier, log loss, 배당 기준과 균등 기준, 확률 구간별 보정 상태를 보여줍니다. 시간순 60/20/20 보고는 있지만 **학습·보정 학습·미사용 평가 기간의 실제 검증은 수행하지 않았습니다**. 과거 데이터를 역으로 채우는 기능도 없습니다. 앞으로 저장할 사전 예측과 공식 종료 결과로 표본을 쌓아야 합니다.

수익률/최대 낙폭은 배당·규칙 확인된 실제 기록만, 경기당 최대 확률 선택에 고정 1,000원 가정으로 계산합니다. 상품별 결과를 분리 평가하므로 다른 대회의 성과를 가져와 정당화하지 않습니다. 기록을 직접 편집하면 무결성을 보장하지 않습니다.

## 구현 상태와 다음 단계

[공식 자료 조사](docs/DATA_SOURCES.md), [검증 기록](docs/VALIDATION.md)을 참고하세요. 현재는 모든 대회에서 예시 및 실제 수동 입력, 종목별 조건부 모형이 있습니다. 실제 데이터 확보·대회별 학습·과거 성능 검증·추천 기준 충족은 모두 미완료입니다. 공식 자료 접근 확인 → 해당 시즌 규칙 및 상품 대응 → 실제 표본 축적 → 대회별 시간순 학습·보정·미사용 기간 평가 순서로 진행합니다.
