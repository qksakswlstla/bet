# 축구 분석·시뮬레이션 실험실

비개발자가 자기 컴퓨터에서 실행할 수 있는 한국어 Streamlit 웹 앱입니다. 첫 버전은 **실험용**입니다. 실제 베트맨 데이터 연결·예측 성능 검증·추천·자동 구매는 제공하지 않습니다. API 키 없이 가상 예시로 시작합니다.

## Windows에서 실행하기

Python **3.12 64비트**를 python.org에서 설치하세요. 설치 시 Python Launcher(`py`) 옵션을 포함합니다. Windows 10/11을 권장합니다.

1. [GitHub 저장소](https://github.com/qksakswlstla/bet)의 `main` 브랜치에서 **Code → Download ZIP**을 선택하고 압축을 풉니다. 폴더 안에 `app.py`, `requirements.txt`, `toto`가 함께 있어야 합니다.
2. `install_windows.bat`을 더블클릭합니다. 최초 한 번 가상환경과 공개 Python 패키지를 설치합니다. 유료 가입은 없습니다. 인터넷 연결이 필요합니다.
3. 설치 성공 후 `start_windows.bat`을 더블클릭합니다. 브라우저가 열리면 앱이 실행된 것입니다. 브라우저가 자동으로 열리지 않으면 명령 창에 표시된 로컬 주소를 브라우저 주소창에 입력하세요.
4. 왼쪽에서 **예시 데이터**를 선택하고 1~6번 화면을 확인합니다. 예시 팀과 결과는 모두 가상입니다.
5. 종료하려면 명령 창에서 `Ctrl+C`를 누릅니다. 다음부터는 시작 파일만 실행하면 됩니다.

배치 파일 대신 직접 실행하려면 **PowerShell을 프로젝트 폴더에서** 열고 다음을 순서대로 입력하세요. 아래 첫 줄의 경로는 `app.py`가 있는 실제 폴더로 바꿉니다.

```powershell
cd "C:\Users\사용자이름\Downloads\bet"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

가상환경 활성화 명령을 쓰지 않으므로 PowerShell 실행 정책을 변경할 필요가 없습니다. 8501 포트를 다른 프로그램이 쓰면 마지막 명령 뒤에 `--server.port=8502`를 붙입니다. Windows에서는 아직 직접 실행하지 않았으며 아래 클라우드 Linux에서 검증했습니다. 이 앱은 외부에 공개 배포하지 않았습니다.

## Linux/macOS·현재 Codex 환경

프로젝트 루트(현재 `/workspace/bet`)에서:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

로컬 브라우저에서 보는 앱입니다. 클라우드 내부 서버 주소를 내 컴퓨터에서 바로 열 수 있다는 뜻은 아닙니다. `requirements.txt`는 직접 의존성의 버전을 고정하며, 전이 의존성을 모두 잠근 크로스플랫폼 잠금 파일은 아닙니다.

## 화면과 사용 순서

1. **경기 목록**: 시작·마감·수집·정보 기준 시각(KST), 실제/예시 구분, 사전 분석 가능 여부를 확인합니다.
2. **검수 결과**: 오류를 먼저 수정합니다. 기대득점이나 배당이 없으면 지어내지 않고 분석을 보류합니다. 출처 충돌·미확정 라인업·24시간 이상 된 자료는 경고합니다.
3. **경기 상세**: 결과 확률, 스코어, 입력 근거, 누락 항목, 배당 마진 조정 확률과 비교합니다. 시각이 유효한 경기의 예측을 저장할 수 있습니다.
4. **시나리오 비교**: 사건 종류를 선택하고 득점률 배수·점수·경과 시간·퇴장 메모·근거를 직접 입력합니다. 재현용 JSON을 내려받습니다. 퇴장 수와 사건 이름은 배수를 자동으로 정하지 않습니다.
5. **조합 비교**: 경기마다 선택지를 고르고 2~3경기 대안을 비교합니다. 최대 10경기, 최대 120개 대안입니다. 각 대안은 입력한 같은 고정 예산으로 각각 비교하며 전부 구매하는 계획은 아닙니다.
6. **성능 기록**: 종료 뒤 공식 결과를 확인하고 예측 ID에 결과를 고정 기록합니다. 배당·정산 확인 체크를 하지 않으면 확률 평가에는 포함되지만 수익 계산에는 포함되지 않습니다.

## 실제 데이터 입력

왼쪽에서 **내 CSV / 붙여넣기 / 직접 입력**을 선택하세요. 양식은 앱 또는 `examples/matches_template.csv`에서 받을 수 있습니다. 한 번에 최대 100경기/2MB, UTF-8(Excel의 CSV UTF-8)입니다. CSV 첫 행은 영문 열 이름을 유지하세요. 쉼표가 포함된 내용은 큰따옴표로 감싸야 합니다. 예시 CSV를 수정할 때 가상 정보·배당·시간을 실제 정보처럼 남기지 마세요. 실데이터에 예시 기대득점을 복사하지 마세요.

| 열 | 입력 내용 |
| --- | --- |
| `sport` | `football` 고정 |
| `match_id`, `league`, `home`, `away` | 고유 경기 ID, 리그, 홈팀, 원정팀. 팀 이름 표기를 통일 |
| `kickoff`, `deadline` | 시작·구매 마감. 예: `2026-11-01T19:00:00+09:00` |
| `source` | 공식 출처 URL·자료명. 복수 출처는 항목별로 구분 |
| `collected_at`, `as_of` | 자료를 수집한 시각, 자료의 정보 기준 시각. 시간대 필수 |
| `kind` | 실제 자료 `real`, 가상 자료 `example` |
| `product` | `1X2_90` 고정. 정규시간 승·무·패 3-way |
| `home_odds`, `draw_odds`, `away_odds` | 동일 상품·동일 시점의 십진 배당, 각각 1 초과~1000 이하 |
| `home_xg`, `away_xg` | 경기 전체 홈·원정 기대득점 **입력 가정**, 0~8. 없으면 빈칸(분석 보류) |
| `xg_basis` | 기대득점을 정한 근거·가정, 개별 정보 출처·기준/수집 시각 |
| `lineup_status` | 선택 사항: `unknown`, `expected`, `confirmed`. 미확보를 confirmed로 쓰지 않기 |
| `source_conflict` | 출처 충돌을 발견했으면 `true`, 없으면 `false` 또는 빈칸 |

선택 항목은 `recent_form`(최근 성적), `opponent_strength`(상대 수준), `home_away_form`, `goals_stats`, `advanced_stats`, `injuries`, `suspensions`, `lineup`, `rest_travel`, `weather_venue`, `odds_history`입니다. 확보하지 못하면 비워둡니다. 각 항목에 출처와 시각을 함께 적을 수 있습니다. **이 항목들은 근거 메모로만 표시하며 자동으로 득점률에 반영하지 않습니다.** 별도로 검증된 학습·선수 영향 추정이 없습니다.

한 행은 동일 시점 자료의 묶음입니다. 행의 `source`, `as_of`, `collected_at`은 그 행의 모든 값에 적용됩니다. 정보별 출처·시각이 다르면 각 메모·`xg_basis`에 항목별 시각을 기록하고, `as_of`는 가장 오래된 기준, `collected_at`은 가장 늦은 수집 시각으로 보수적으로 기록하세요. 마감 후 수집한 정보가 섞인 행은 사전 입력으로 사용하지 않습니다. 원자료 파일도 보관하세요. 자동 진위 검증은 하지 않습니다.

스포츠·상품·기준점이 다른 행을 섞지 마세요. 지원하지 않는 열에 값이 있으면 오류로 처리합니다. 다른 상품의 배당을 승무패 열에 옮겨 적는 오류까지 자동 판별할 수는 없습니다. 팀 별칭(예: 맨유/Manchester United)의 동일성도 자동 확인하지 않습니다. 스크린샷 인식은 지원하지 않습니다.

## 계산 가정

- **포아송 모형**: 입력 기대득점 λ를 사용해 `P(G=k)=exp(-λ)λ^k/k!`로 계산합니다. 두 팀 득점은 독립, 득점률은 일정합니다. 학습·최적화된 팀 전력 모형이 아닙니다. 0~60골 격자에서 확률을 합산·정규화합니다. 입력 범위 0~8에서 잘린 꼬리는 매우 작습니다.
- 예상 득점은 입력한 기대값이며 실제 점수를 약속하지 않습니다. 저득점 상관, 전술 변화, 실제 라인업/선수 효과, 일정·날씨 효과를 학습하지 않았습니다.
- **배당 확률**: 역배당 `1/o`의 합에서 1을 뺀 값이 표기 마진입니다. 역배당을 합으로 나눠 비례 조정합니다. 이것도 실제 확률의 정답은 아닙니다.
- 가상 상품 계산은 정수 **유럽식 3-way 홈 핸디캡**과 **반골 언더오버**만 지원합니다. 실제 상품에 연결하지 않습니다. 아시안·쿼터·정수 U/O·연장·승부차기 상품의 입력/추천/정산은 미지원입니다.
- **시나리오**: 남은 득점 기대값 = 경기 전 기대득점 × 사용자 배수 × `(90−경과분)/90`. 현재 점수를 더합니다. 발생 확률은 미확보이며 사건별 조건부 결과만 비교합니다. 겹치는 시나리오를 합산하지 않습니다. 추가시간·퇴장 효과를 자동 추정하지 않습니다.
- **몬테카를로**: 실행 1천~20만 회, 시드, 모형 버전, 입력·출처·시각을 JSON에 기록합니다. 표본오차는 모형 불확실성을 포함하지 않습니다. 정확 합산 확률도 함께 표시합니다.
- **조합**: 경기 간 독립을 가정한 확률곱·배당곱입니다. 상관은 추정하지 못했습니다. 두 팀 기대득점을 각각 ±20% 바꾼 9개 가정의 범위는 통계적 신뢰구간이 아닙니다(0~8 범위 밖 가정은 제외).
- 기대순손익 = `고정 예산 × (추정 확률 × 배당 − 1)`. 적중하면 배당곱만큼 반환, 하나라도 미적중이면 반환 0을 가정합니다. 비교 금액은 자동 구매·증액으로 연결되지 않습니다.
- **정산 계산기**: 적중 배당 적용, 미적중 0, 취소/적특 배당 1, 전부 취소 시 원금 반환이라는 명시적인 단순 가정입니다. 베트맨 실제 상품별 규칙·조합 가능 여부·세금·한도는 연결하지 않았습니다.
- 실제 자료가 충분해도 지금은 추천을 활성화하지 않습니다. 모형 오차와 실구매 규칙이 검증되지 않아 항상 **추천할 조합 없음**입니다.

## 기록과 과거 평가

예측 저장 시 입력 전체·배당·생성 시각·모형 버전·확률을 SQLite에 저장합니다. 한 경기/실제·예시 구분별 첫 예측만 유지하며 결과도 덮어쓰지 않습니다. CSV를 올린 것만으로 기록이 남지는 않습니다. `data/history.sqlite3`을 앱을 끈 뒤 복사하면 백업할 수 있습니다. JSON 내보내기도 제공합니다. `data/`는 Git에 포함하지 않습니다. 위치 변경은 선택 환경변수 `BET_DATA_DIR`로 설정할 수 있습니다.

마감/시작 후의 새 사전 예측을 막고, 평가 시에도 `정보 기준 ≤ 수집 ≤ 예측 생성 < 구매 마감 ≤ 시작`을 검사합니다. 로컬 DB 직접 수정·잘못 입력한 출처까지 방지하는 감사 시스템은 아닙니다. 실제와 예시 결과는 따로 평가합니다.

- 시간순 60/20/20 구간을 표시합니다. **학습은 미실시**이며 고정 모형의 참고/검증/별도 평가 보고용 분리입니다. 조정에 사용하지 않은 평가 기간인지 자동 입증하지 않으므로 검증 완료를 표시하지 않습니다. 모형을 조정한 뒤에는 새로운 미래 평가 기간을 확보해야 합니다.
- 적중률, 다중분류 Brier(제곱오차 합 평균, 0~2), 자연로그 log loss, 20% 폭의 확률 보정 표를 제공합니다. 보정 학습은 없습니다. 배당 마진 조정·각 결과 1/3 기준과 비교합니다.
- 수익률은 당시 실제 구매 가능 배당과 단순 정산 규칙을 사용자가 확인한 **종료 경기**만 대상으로, 최대 확률 선택에 매 경기 고정 1,000원을 썼다는 가정입니다. 표본·기간·투입 대비 순손익·최대 낙폭을 표시합니다. 조합 수익 검증은 아닙니다.
- 취소·미확보 결과는 지표와 투입액에서 제외하고 사유를 표시합니다. 무승부는 취소가 아니라 정상 결과입니다.
- 과거 예측 일괄 역입력·자동 과거 배당 수집은 미지원입니다. 새로 저장한 사전 예측을 앞으로 기록하거나 **합성 과거 30경기**로 계산 흐름만 확인합니다. 합성 성과를 실전 성능으로 해석하면 안 됩니다.

## 테스트

프로젝트 폴더의 PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

테스트는 확률의 알려진 값·합계, 시뮬레이션 재현성, CSV 오류·시간/상품 검수, 조합·취소 정산, 예측 고정 저장·미래 정보 제외, 평가 지표·기준 모형·시간 분리, Streamlit 화면 입력 흐름을 확인합니다. 구체적인 실행 결과와 미검증 사항은 [검증 기록](docs/VALIDATION.md)을 참고하세요.

## 파일 구조와 확장

`app.py`는 한국어 화면, `toto/validation.py`·`input.py`는 입력, `model.py`는 확률·시뮬레이션, `combinations.py`는 조합·명시적 정산, `history.py`는 기록·평가, `demo.py`는 가상 자료입니다. `tests/`는 계산·화면 테스트입니다. 모델 버전과 종목·상품 구분을 보존하므로 공급원 어댑터·다른 종목 모형을 별도 모듈로 추가할 수 있습니다.

다음 우선순위는 사용 허용된 실제 자료 확보 → 사전 기록 축적 → 기대득점 추정·시간순 학습 → 미사용 기간 성능·보정 검증 → 실제 상품·정산 대응 확인입니다. 자동 수집·실시간 연결은 그 뒤에 별도 검증합니다. [데이터 출처와 접근 확인 결과](docs/DATA_SOURCES.md)를 참고하세요.
