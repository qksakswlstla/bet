## 키 준비

- 일정·점수: [API-Sports 공식 사이트](https://api-sports.io/) 또는 [API-Football](https://www.api-football.com/)의 공식 Dashboard/등록 메뉴에서 계정과 직접 접속용 키를 준비합니다. 필요한 종목의 이용 권한·현재 무료 한도를 먼저 확인하세요. 환경변수 이름은 **APISPORTS_KEY**입니다. RapidAPI용 키/헤더는 이 어댑터에서 지원하지 않습니다.
- 해외 배당 참고: [The Odds API](https://the-odds-api.com/) 공식 사이트의 API 키 발급 메뉴에서 준비합니다. 환경변수 이름은 **ODDS_API_KEY**입니다. 이 기능은 선택 사항이며 일정 조회에는 필요 없습니다.
- 실제 가입 화면·최신 무료 조건을 이 환경에서 확인하지 못했습니다. 결제가 요구되면 중단하고 비용과 제한을 검토하세요. 프로그램이 결제를 진행하지는 않습니다.
- 키를 채팅·CSV·GitHub·배치 파일에 쓰지 마세요. 앱에는 키 입력란을 만들지 않았습니다.

## Windows 실행 순서

1. 기존 앱을 Ctrl+C로 종료하고 GitHub 최신 ZIP으로 업데이트합니다. 기존 `data`는 별도 백업합니다.
2. 새 폴더의 `install_windows.bat`으로 설치합니다.
3. **app.py가 있는 폴더에서 PowerShell을 열고** 아래를 실행합니다. 키를 입력할 때 화면에 보이지 않습니다. `Read-Host` 프롬프트에 붙여넣으며 명령문에 직접 키를 적지 마세요.

```powershell
cd "C:\Users\사용자이름\Downloads\bet-main"
$apiSportsSecret = Read-Host "API-Sports 키" -AsSecureString
$env:APISPORTS_KEY = [System.Net.NetworkCredential]::new("", $apiSportsSecret).Password
Remove-Variable apiSportsSecret
.\.venv\Scripts\python.exe scripts\check_provider.py basketball
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

농구 대신 `volleyball` 또는 `football`로 바꾸면 해당 대회 목록 연결을 점검합니다. 키값은 출력하지 않습니다. `status: ok`여도 특정 대회의 현재 시즌 지원까지 증명한 것은 아닙니다. 이 점검 자체도 공급원 호출 한도를 사용할 수 있습니다.

해외 배당도 사용하려면 **앱 실행 전에 같은 PowerShell 창에서** 추가합니다.

```powershell
$oddsSecret = Read-Host "The Odds API 키" -AsSecureString
$env:ODDS_API_KEY = [System.Net.NetworkCredential]::new("", $oddsSecret).Password
Remove-Variable oddsSecret
```

`$env:` 설정은 해당 PowerShell과 그 창에서 시작한 앱에만 전달됩니다. 별도로 배치 파일을 더블클릭하면 키가 전달되지 않을 수 있습니다. 창을 닫은 뒤에는 다시 설정해야 합니다. Windows에서 위 흐름을 직접 실행한 것은 아니며 사용자 환경에서 확인해야 합니다.

## 앱 사용 순서

1. 왼쪽에서 대상 대회와 KOVO 부문을 선택한 뒤 **자동 경기 불러오기**로 이동합니다.
2. **공급원 대회·시즌 목록 조회**를 누릅니다. 공급원 이름·국가·유형·ID·시즌·원자료를 확인합니다. 카탈로그에는 다른 대회도 검색 후보로 보이지만 입력 대상은 지정한 다섯 대회입니다.
3. 대회·남녀부·정규/컵·시즌 일치를 확인한 뒤 확인란을 선택합니다. 이 작업은 사용자 확인이며 이름 유사도만으로 자동 확정하지 않습니다. 현재 시즌이 무엇인지 앱이 추측하지 않습니다.
4. 한국 시간 기준 최대 31일 범위를 지정하고 **경기 불러오기**를 누릅니다. **새로고침**도 실제 네트워크 재요청입니다. 자동 주기 호출·자동 재시도는 없습니다.
5. 반환 경기 ID·팀·시작 시각·상태·점수 원자료와 출처/수집 시각을 확인합니다. **반환된 경기 원자료 대조**에서 같은 경기인지 확인합니다. 공급원 업데이트 시각이 응답에 없으면 `미확보`로 표시합니다.
6. 원자료 확인란 → **확인한 일정으로 수동 입력 채우기**를 누릅니다. 왼쪽에서 **실제/예시 자료 입력 → 한 경기 직접 입력**으로 이동하면 자동 확보한 일정이 채워집니다.
7. 베트맨 판매 경기와의 일치, 실제 상품·배당·기준점·마감, 정보 기준 시각, 공식 정산 규칙과 모형 입력을 직접 확인합니다. 빠진 정보는 자동 생성하지 않으므로 분석은 보류됩니다.

직접 접속용 후보 엔드포인트는 Basketball/Volleyball의 `/leagues`, `/games?league=…&season=…`, Football의 `/leagues`, `/fixtures?league=…&season=…`, The Odds API의 `/sports`, `/sports/{key}/odds`입니다. 목록 조회/새로고침 각 동작은 최대 1회 요청이며, 한 응답이 여러 페이지임이 확인되면 부분 자료를 전체 성공으로 표시하지 않습니다. 종목별 날짜 필터를 추측하지 않고 시즌 응답을 한국 시간으로 필터링합니다. 시즌 응답이 너무 크거나 페이지가 나뉘면 현재 버전에서 가져오기를 완료하지 못할 수 있습니다.

## 보존·매칭·갱신 기준

- 자동 자료는 `data/auto_sources.sqlite3`에 저장합니다. `BET_DATA_DIR`가 있으면 그 위치를 사용합니다. 수동 예측 DB와 분리됩니다.
- 공급원 종목+팀 ID/경기 ID로 내부 ID를 만듭니다. 예: `apisports:basketball:team:1`. 공급원 표시 이름이 바뀌어도 같은 ID면 같은 팀입니다. 대회·시즌·남녀부는 별도 범위로 보존합니다.
- 동일 공급원 대회·시즌을 KOVO 남녀부 양쪽에 연결하는 등 충돌은 거부합니다. 다른 공급원이나 기존 수동 ID와 자동 병합하지 않습니다. 같은 팀/경기 여부를 직접 대조하고 ID를 통일해야 합니다.
- 해외 배당 경기와 일정 경기의 자동 매칭은 하지 않습니다. 해외 배당에는 항상 `매칭 미확정`, `베트맨 아님`을 표시합니다.
- 자동 항목: 공급원 ID, 팀 이름, 일정·시작 시각, 반환된 단계·상태·점수, 요청 출처·수집 시각. 자동 점수는 최종 정산 결과로 확정하지 않습니다. `auto_provenance`에 원래 ID·출처·수집 시각·점수·매핑을 남깁니다.
- 직접 확인할 항목: 베트맨 판매 여부·배당·기준점·마감·정산, 공급원 자료 기준 시각이 없을 때의 근거, 모형 입력, 통계/선수 정보. 수집 시각을 공급원 갱신 시각으로 바꾸지 않습니다.
- `ok`(목록 있음), `empty`(정상 조회 0건), `missing_key`, 권한 실패, 호출 한도, 연결 실패, 형식 불일치, 부분 응답을 구분합니다. 실패하면 예시나 이전 성공 목록을 최신으로 표시하지 않습니다.
- 마지막 성공·마지막 시도 시각을 별도 보존합니다. 일정/카탈로그 24시간 경과 시 재조회 전 가져오기 보류. 해외 배당은 공급원 갱신 시각 기준 15분 초과·미확보이면 사용 보류 표시입니다. **24시간/15분은 앱의 운영 경고 기준이며 공급원 공식 갱신 주기가 아닙니다.** 최신이라고 단정하지 않습니다.
- 해외 배당은 유럽 지역 `h2h` 참고 조회만 구현했습니다. 정산 범위 미확인이므로 기존 분석/조합의 베트맨 배당 칸에 넣지 않습니다. 오래된 값은 원자료 참고로만 표시합니다.
- 공급원 통계/선수 상세 엔드포인트, 계수 학습, 자동 추천은 추가하지 않았습니다.

## 베트맨 및 접근 설정

베트맨의 공식 제공/API·수집 허용 범위를 확인하지 못했습니다. 로그인·인증 우회, 비공개 엔드포인트 추측, 자동 스크래핑을 구현하지 않았습니다. 해외 배당을 베트맨 배당으로 대체하지 않습니다. 사용자가 이용 가능한 공식 화면 자료를 직접 입력하는 기존 경로를 유지합니다.

Codex 클라우드에는 공급원 API 호스트 4곳과 공식 문서/요금·베트맨 조사 호스트 4곳, APISPORTS_KEY/ODDS_API_KEY 요구사항을 **설정 초안으로 저장**했습니다. 키 값은 저장하지 않았습니다. 환경 설정에서 안전하게 값을 입력하고 변경 사항을 검토·저장한 뒤 환경 게시가 필요합니다. 초안 저장만으로 현재 프록시 정책이나 키 주입이 적용되었다고 주장하지 않습니다. Windows에서는 해당 PC의 네트워크와 환경변수를 사용합니다.

## 검증 수준

- 키 없이 확인: 기존 테스트 및 합성 응답의 ID 매핑, KST 범위, 시즌 불일치, 부문 충돌, 누락/빈 결과/실패, 과거 스냅샷 표시, 오래된 배당 보류, 비밀값 비노출, 자동 조회→원자료 확인→수동 입력 화면 흐름.
- 공급원 응답 테스트 자료는 **합성 픽스처**이며 실제 API 캡처가 아닙니다.
- 실제 API 키/실제 경기 반환/원자료 대조: **미실행**. 실제 연결 성공을 보고할 근거가 없습니다.
- Windows 직접 실행: 미실행. 위 절차로 키를 설정하고 실제 공급원 원자료와 경기·팀·시각을 대조해야 합니다.

최종 로컬 검증: 전체 **89개 테스트 통과**, 의존성 충돌 없음. 앱을 새로 시작해 `/` HTML과 `/_stcore/health` `ok`를 HTTP 200으로 확인했습니다. `scripts/check_provider.py basketball`을 실제 실행한 결과는 **missing_key**였으며 실제 API 호출은 이루어지지 않았습니다. 합성 응답 화면 테스트와 실제 연결 성공을 혼동하지 않습니다.

## 공급원 오류 상세 표시 수정 (2026-10-29 KST)

오류 응답의 `errors` 항목·설명을 비밀값/개인정보 필터를 거쳐 저장하고 화면에 표시합니다. 요청 종목·대회 ID·시즌도 함께 기록합니다. HTTP 오류 응답이 제한된 크기의 JSON인 경우에도 errors/message를 확인합니다. 원문 HTTP 헤더·전체 요청 URL·인증값을 로그로 출력하지 않습니다.

설명 문구에 시즌/요금제 제한, 인증 실패, 호출 한도, 요청 조건 오류의 명시적 근거가 있을 때만 분류합니다. 근거가 없으면 원인 미확인입니다. NBA 2026-2027의 실제 실패 원인은 새 응답을 확인하기 전에는 단정할 수 없습니다.

기존 앱을 Ctrl+C로 종료하고 최신 GitHub ZIP으로 업데이트한 뒤, 키를 설정한 동일 PowerShell에서 앱을 다시 실행하세요. 대회 목록·경기 조회를 새로 요청하면 상세 오류가 나타납니다. 이전 버전이 버린 오류 내용은 저장 DB에서 복구할 수 없습니다.
