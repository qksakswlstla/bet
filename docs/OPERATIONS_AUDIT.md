## 데이터 경로 증거

- `app.py`의 직접 입력/CSV → `validate` → `analyzable` → `simulate`. 코드에 경기 일정·배당·선수 API 호출 클라이언트가 없습니다.
- `demos()`는 예시 모드 전용 합성 팀·일정·배당·모형 입력을 만듭니다. 2.0/3.0 같은 배당과 종목별 예시 모형값은 실제 값이 아닙니다. 학습값이나 추천 점수로 사용하지 않습니다.
- 실제 입력의 경기 일정과 배당은 사용자가 입력한 값, 선수 정보는 사용자 `evidence`/`basis` 메모입니다. 선수별 영향 계수를 자동 추정하지 않습니다.
- 네트워크 실패를 예시로 바꾸는 경로는 발견하지 못했습니다. API 자체가 없으므로 연결 정상 여부도 성립하지 않습니다.
- KBL/KOVO/NBA/J리그컵/AFC/베트맨 공식 주소에 읽기 전용 GET을 재실행했으나 모두 프록시 CONNECT 403. 외부 연결은 검증하지 못했습니다. 공급원 자체의 권한·장애를 확인한 것은 아닙니다.
- 예시 생성 시각을 세션 내에서 고정했습니다. 입력 목록에 출처·공급원·수집/기준 시각(KST)과 자동 갱신 없음 표시를 추가했습니다.

## 수정한 오류

1. 수치 문자열이 범위 검사를 통과한 뒤 연산에서 실패: 계산 전에 float로 일관되게 변환.
2. 빈 시나리오 사전 `{}`가 원본 입력으로 조용히 대체: 필수값 오류로 처리. 미지원 변수(예: red_cards)를 조용히 무시하지 않고 계산 보류.
3. 정산 함수를 직접 호출할 때 미지원 정수 총득점이 동점 환급 대신 언더로 판정될 여지: 정산과 모형 입구에서 지원 상품·기준점을 검수하여 거부.
4. 개별 근거의 기준 시각이 수집 시각보다 늦어도 통과: 개별 시각 순서 검수 추가.
5. CSV 파싱 실패 뒤 이전 입력이 다음 재실행에 복귀할 여지: 실패 시 세션 자료도 제거. 새 자료를 같은 행 위치에 넣을 때 이전 시나리오 위젯 수치가 남지 않도록 자료별 키 사용.
6. 원래 축구 주요 스코어가 원시 발생 건수: 실행 횟수로 나눈 확률로 수정.
7. 경기 중 조건이 조합에 포함될 여지: 사전 조합·기록에서 제외. 마감 자료 상세에는 과거 조건부 계산 표시.
8. 성능 기록의 확률 합계·범위, 입력 스냅샷, 상품·대회, 공식 결과와 정산 일치, 결과 시각, 중복 표본 검수 부족: 평가 직전 재검사하고 제외 사유 표시.
9. 정산 표본 0개인데 최대 낙폭 0 표시: null(산출 불가)로 변경. 임의 0~1 조합 불확실성 대용값도 제거해 미추정 상태 유지.
10. 같은 시작 시각 경기가 60/20/20 경계를 넘을 수 있음: 서로 다른 시작 시각을 기준으로 분리. 학습 실행이나 실제 미사용 평가 기간 검증은 아님.

## 계산·시나리오 추적

화면 확률은 `simulate()`의 표본 사건 비율입니다. 마진 조정은 역배당 합으로 정규화, 단일/조합 기대순손익은 예산×(추정 확률×십진 배당−1)입니다. 조합은 다른 경기 확률곱·배당곱이며 독립 가정의 실험값입니다. 같은 경기의 여러 상품은 제외합니다. 실제 상품 조합 제한·세금·환급/취소·진출 정산은 미검증/미지원입니다.

사건 이름(선수 결장·퇴장 등)은 메모이고 그 자체로 수치를 바꾸지 않습니다. 변경한 효율/속도/기대득점/랠리 확률/피로/교체 값이 계산에 도달하는 것은 테스트했습니다. 그 영향 크기가 실제 선수 효과라는 근거는 없습니다. UI에 이 구분과 농구 점수차 5/15, 배구 확률 제한 등의 가정을 명시했습니다. 실제 학습한 신뢰도·추천 점수는 없습니다.

동일 시드/입력 재현성을 여섯 대회·부문 예시에서 확인했습니다. 5개 시드(11,22,33,44,55)의 홈 승률 표준편차:

| 합성 모형 | 1,000회 | 20,000회 |
|---|---:|---:|
| KBL/NBA 예시 | 1.290%p | 0.568%p |
| KOVO 각 부문 예시 | 1.537%p | 0.330%p |

같은 종목 예시의 가정값이 같아서 결과도 같습니다. 실제 대회별 계수가 같다는 뜻이 아닙니다. 이는 이번 합성 표본에서 관측한 난수 변동이며 횟수 증가가 언제나 단조롭게 오차를 줄이거나 실제 예측 정확도를 높인다는 주장도 아닙니다. 원시 결과는 `audit_evidence.json`에 저장했습니다.

## 과거 검증의 범위

구현된 것은 **앞으로 저장한 사전 예측과 종료 결과의 평가기**입니다. 과거 원자료를 당시 상태로 재구성해 반복 학습하는 백테스트, 학습/보정 파이프라인, 미사용 평가 기간 확보는 구현·검증하지 않았습니다. 시간순 분할을 했다는 이유로 백테스트 완료라고 할 수 없습니다.

클라우드 실제 사전 예측 0개, 유효 종료 결과 0개. 모든 대회/부문의 실제 평가 기간, Brier, log loss, 보정 결과, ROI는 산출 불가입니다. 필요한 자료는 경기 전 입력·그때 구매 가능했던 배당·그때의 규칙·출처/시각·공식 종료 결과입니다. 최소 검증 표본 수는 목표 오차/기간을 정해 설계해야 하며 여기서 임의 숫자로 정하지 않았습니다.

대회/시즌/부문/상품/기준점/규칙/모형/실제·예시를 분리한 지표와 제외 사유를 화면에 표시합니다. ROI/최대 낙폭은 확인된 배당이 있는 실제 종료 표본만 계산합니다. 고정 1,000원 최대확률 선택과 경기 시작순 누적이라는 가정이며 실제 거래 내역·현금흐름 검증이 아닙니다. 같은 시각 경기의 순서 및 별도 기간 선택의 영향, DB 수동 변경·입력 출처의 진위까지 보증하지 않습니다.
